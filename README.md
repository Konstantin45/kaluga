# Kaluga: демо камеры и дисплея

## Используемое оборудование

- Основная плата: **ESP32-S2-Kaluga-1 v1.2**.
- Экран: **ESP-LyraP-LCD32 v1.1**.
- Сенсорная панель: **ESP-LyraP-TouchA v1.1**.
- Камера: **ESP32-LyraP-CAM v1.0**.
- Аудиоплата: **ESP-LyraT-8311A v1.2**.

Для камерного режима LCD32 устанавливается непосредственно на основную плату,
без ESP-LyraT-8311A в стеке. Аудиоплата v1.2 делит с CAM v1.0 интерфейс камеры
и GPIO46, поэтому их совместная работа на Kaluga-1 v1.2 не поддерживается.
TouchA и камера подключаются своими FPC-шлейфами. Перед включением проверьте,
что шлейфы вставлены ровно, до упора, а защёлки закрыты. Конфигурацию стека и
DIP-переключатели меняйте только при выключенном питании.

## Текущий приоритет демо

Первый режим — камера: нажатие сенсорной кнопки `Record` выполняет снимок и
показывает кадр на LCD. При запуске Wi-Fi сканирует эфир и временно показывает
на экране список ближайших сетей. Подключение к сети можно включить и настроить
через `idf.py menuconfig`; пароль не хранится в исходном коде.

Адресный RGB-светодиод в камерном режиме отключён: на Kaluga-1 v1.2 его GPIO45
одновременно является линией D1 камеры. Состояние запуска, готовности, съёмки и
ошибок показывается на LCD.

Аудио в первом этапе отключено, а плата ESP-LyraT-8311A физически снимается из
стека на время камерного режима.

## Ограничения сенсорной панели

LCD32 v1.1 содержит резистивный сенсорный слой и контроллер NS2016, но готового
драйвера для него в Kaluga BSP нет. Его линии `TP_IRQ`, `TP_BUSY`, `TP_MISO`,
`TP_MOSI`, `TP_SCK` и `TP_CS` пересекаются с линиями CAM. Поэтому группа DIP
`Touch Screen Switch` на LCD32 должна оставаться целиком в положении `OFF` в
камерном режиме. Встроенный тач LCD можно будет использовать отдельным режимом
только при отключённой камере.

У TouchA пять кнопок используют GPIO, занятые камерой или LCD. В режиме камеры
надёжно доступна только кнопка `Record` на GPIO5 / Touch5; именно она запускает
съёмку. `VOL_UP`, `PLAY`, `VOL_DOWN`, `PHOTO` и `NETWORK` прошивка намеренно не
инициализирует. Чтобы освободить дополнительные кнопки, нужна аппаратная
доработка платы.

GPIO45 не используется для RGB-индикации, пока активна камера.

## Зависимости и сборка

ESP-IDF уже установлен в `/home/ubuntu24/esp/esp-idf` (версия 6.1).
Зависимости проекта ESP-IDF загрузит автоматически в папку проекта при первой
сборке; отдельно копировать их в общий каталог ESP не нужно.

```bash
cd /home/ubuntu24/esp/kaluga
source /home/ubuntu24/esp/esp-idf/export.sh
idf.py build
```

## Подключение платы к WSL и прошивка

1. Подключите Kaluga по USB к Windows.
2. В **PowerShell от имени администратора** выполните:

   ```powershell
   usbipd list
   usbipd bind --busid <BUSID>
   usbipd attach --wsl --busid <BUSID> --auto-attach
   ```

   `bind` обычно требуется только один раз. Команду `attach --auto-attach`
   оставьте запущенной: она повторно подключит ESP32 после перезагрузки. Если
   `usbipd` отсутствует, его нужно установить в Windows (usbipd-win), а не в
   WSL.
3. В WSL определите порт:

   ```bash
   ls -l /dev/ttyACM* /dev/ttyUSB*
   ```

   В этом комплекте FTDI создаёт два порта: `/dev/ttyUSB0` используется для
   JTAG, а `/dev/ttyUSB1` — для UART-прошивки и монитора.
4. Прошейте через UART на скорости 460800. Если автоматический reset или запись
   с подключёнными расширениями срывается, отключите питание, временно снимите
   CAM и ESP-LyraT-8311A и повторите прошивку:

   ```bash
   cd /home/ubuntu24/esp/kaluga
   source /home/ubuntu24/esp/esp-idf/export.sh
   idf.py -p <ОБНАРУЖЕННЫЙ_ПОРТ> -b 460800 flash
   ```

5. После успешной прошивки подключите CAM, подайте питание и один раз
   перезапустите плату. Аудиоплата в первом, камерном режиме программно не
   используется.

Перед прошивкой закройте программы Windows, которые держат последовательный
порт. Для просмотра журнала отдельно можно запустить `idf.py -p <ПОРТ> monitor`;
для выхода используйте `Ctrl+]`.
